# NoneBot 群管整合

独立的 NoneBot2 / OneBot v11 插件：入群申请审批、可选成员来源统计、极验网页验证与本地算术回退。

## 安装与加载

要求 Python 3.10+，NoneBot2 2.4.4+ 与 OneBot v11 适配器；HTTP 与图表依赖由安装器声明安装，不需要 AstrBot 或 matplotlib。

在机器人项目的虚拟环境中安装本地源码或构建后的 wheel：

```shell
python -m pip install /path/to/nonebot-plugin-group-guard
# 或
uv pip install /path/to/nonebot-plugin-group-guard
```

在 `nonebot.init()` 后加载：

```python
nonebot.load_plugin("nonebot_plugin_group_guard")
```

也可将 `src/nonebot_plugin_group_guard/` 复制到机器人自己的插件目录，由 `load_plugins` 加载；安装版与复制版只能加载其中一份。

默认配置与状态分别为**启动工作目录**下的 `data/group_guard/config.json`、`state.json`，不会写入安装包目录。可在 NoneBot 配置中指定绝对路径：

```dotenv
GROUP_GUARD_CONFIG_FILE="/path/to/group_guard/config.json"
GROUP_GUARD_STATE_FILE="/path/to/group_guard/state.json"
```

新配置默认总开关关闭、审批白名单为空、各群验证关闭；加载插件不会自动接管任何群。配置文件不存在时只读取安全默认值，管理命令保存后才创建文件。

## 审批与来源是两回事

| 模式 | 适用问题 | 行为 |
| --- | --- | --- |
| `legacy`（兼容，默认） | 原来询问入群来源的关键词配置 | 拒绝词优先，再按原分类关键词包含匹配；未命中转人工 |
| `rules`（规则） | 固定答案、多个正确答案、可归纳关键词的问题 | 按允许规则完整匹配或包含匹配；拒绝词优先，未命中转人工 |
| `manual`（人工） | “为什么想加入”等无法穷举答案的问题 | 不自动批准或拒绝，交管理员判断 |

审批与入群后的人机验证独立：人工批准的成员仍可按该群设置进行极验/算术验证。

`rules` 的单条规则示例：

```json
{
  "name": "成员知识题",
  "match": "exact",
  "values": ["花帆", "吟子"],
  "case_sensitive": false
}
```

- `exact`：去除两端空白后完整匹配；一个答案或多个候选答案都用 `values` 列表。
- `contains`：关键词包含匹配，适合能明确归纳关键词的开放答案；不做语义猜测。
- `name` 是审批规则名称，**不会**被当作成员来源。
- 只有显式设置 `source` 才映射来源，例如 `"source": "GitHub"`；不从答案、规则名或审批原因推断。
- 仅匹配申请者实际回答，不把 `问题：…\n答案：…` 中的问题正文算入答案；格式不明确留人工。

按群配置示例（放在配置的 `approval.group_rules` 下）：

```json
{
  "10001": {
    "approval_mode": "rules",
    "accept_rules": [
      {"name": "成员知识题", "match": "exact", "values": ["花帆", "吟子"]}
    ],
    "source_statistics": false
  },
  "10002": {
    "approval_mode": "rules",
    "accept_rules": [
      {"name": "开源社区入口", "match": "contains", "values": ["github"], "source": "GitHub"}
    ],
    "source_statistics": true
  },
  "10003": {"approval_mode": "manual"}
}
```

群号示例只展示分群规则，不会自动扩大审批范围；仍需在该群开启申请审批。

`approval_mode`、`accept_rules`、`source_statistics` 也可作为全局字段，群级未指定项继承全局。`source_statistics` 省略或为 `null` 时，仅兼容模式默认启用；规则/人工模式默认关闭。原 `accept_categories`、`reject_key`、模板、通知目标和历史 `category` 记录保持兼容。

来源图仅统计仍保留且具有来源分类的记录，新记录的空来源不强行归类；不会把通过知识题、人工审批等当作来源。默认水印 `©PL!HS ©S ©2023 BNML ©ODD No. Generated by KhBot`，按水印所在区域的背景亮度自动选深/浅色，附细反色描边以适应复杂背景。

完整字段语义见 [审批与来源分类](docs/approval-rules.md)。

## 命令

前缀跟随机器人的 `COMMAND_START`，以下用 `/` 举例；除统计图外，管理命令限当前群群主、管理员或 Bot 超级用户，总开关仅超级用户。

| 命令 | 用途 |
| --- | --- |
| `/群管帮助` | 命令总览 |
| `/群管总开关 开启\|关闭` | 总开关，不会停止其它进程的群管 |
| `/群管审批 开启\|关闭` | 当前群申请审批范围 |
| `/群管审批模式 兼容\|规则\|人工` | 当前群审批方式 |
| `/群管规则 查看` | 查看规则名和匹配方式，不公开答案 |
| `/群管规则 添加 JSON` | 按名称新增/替换一条规则 |
| `/群管规则 删除 规则名` | 删除当前群规则 |
| `/群管来源统计 开启\|关闭\|默认` | 独立设置来源统计 |
| `/群管关键词 查看` | 原兼容分类与拒绝词 |
| `/群管关键词 允许添加 分类:词1,词2` | 原兼容模式分类关键词 |
| `/群管关键词 允许删除 分类` | 删除原兼容分类 |
| `/群管关键词 拒绝添加\|拒绝删除 关键词` | 拒绝词，人工模式不自动处理 |
| `/开启验证`、`/关闭验证` | 当前群入群后验证 |
| `/查看验证配置`、`/待验证列表` | 当前群配置与待处理状态 |
| `/重新验证 @成员` | 强制重新验证，不受等级免验绕过 |
| `/绕过验证 @成员`、`/取消绕过验证 @成员` | 持久免验；取消免验不立即重验 |
| `/设置验证超时时间 秒` | 30～86400 秒 |
| `/设置验证错误次数 次` | 1～100 次 |
| `/设置踢出延迟 秒` | 0～300 秒 |
| `/开启等级验证`、`/关闭等级验证` | QQ 等级免验 |
| `/设置最低验证等级 等级` | 0～256 |
| `/开启网页验证`、`/关闭网页验证` | 极验网页或算术验证 |
| `/入群统计`、`/加群统计` | 可选成员来源图 |

固定答案建议直接在本机 JSON 中配置，不要在群里发送真实口令。规则模式的自动审批通知不会回显完整申请答案；自行配置包含 `%comment%` 的模板仍可能主动公开该字段。

## 极验、通知与素材

- `verification.api_base_url`、`api_key` 配置现有兼容后端；创建/校验服务故障时改用本地 0～100 加减法题，不把基础设施错误记作答错。
- `verification.group_configs` 的条目按 `group_id` 设置 `enabled`、时限、次数、网页验证、等级门槛与模板，未覆盖项继承全局。
- 通知目标支持 `origin`、`group:群号`、`private:QQ号`，兼容 `default:GroupMessage:群号`、`default:FriendMessage:QQ号`。
- 欢迎模板支持 `%group_id%`、`%user_id%`、`%user_name%`、`%category%`、`%key%`、`%comment%`；验证模板支持 `{member_name}`、`{question}`、`{timeout}`（分钟）、`{timeout_seconds}`、`{countdown}`、`{count}` 等。
- 仅受控 `{at_user}` / `%at_user%` 转换为 @ 消息段，用户输入与其它 CQ 字符串维持普通文本；图片在机器人侧生成并按字节发送。
- `approval.assets_dir` 指向自行提供的素材目录，`font` 为相对字体文件名，`bg_img` 为后备背景；存在 `background/` 时随机选取其中图片。建议使用绝对素材路径，未配置素材也可用内置纯色背景和系统字体。
- 字体、背景及游戏素材不随源码分发，使用者须自行确保使用权限。

## 从 AstrBot 对应插件迁移

安装后使用离线命令，不需要先初始化 NoneBot：

```shell
group-guard-migrate --astrbot-root /path/to/AstrBot --output-dir /path/to/group_guard
# 或
python -m nonebot_group_guard_migrate --astrbot-root /path/to/AstrBot --output-dir /path/to/group_guard
```

迁移只读 `astrbot_plugin_joinmanager`、`astrbot_plugin_group_combined_captcha_verify` 的配置与来源记录；输出 `config.json`、`state.json`，已有目标一律拒绝覆盖，新总开关关闭。按需复制字体与背景，较大或软链接素材目录只引用原路径，不能先删掉原素材。单独的旧数学 PRO 不额外迁入。

迁移到非默认目录后，设置上面的两个配置路径。源码直接执行也可使用 `python src/nonebot_plugin_group_guard/migration.py --help`。

同一账号的多个框架/进程均可能收到相同事件，`priority` 与 `block` 无法跨进程互斥；必须先停旧端对应功能，再重启目标机器人加载此插件，检查配置后启用总开关，最后在受控测试群验收。

## 故障安全与数据

- 会话以机器人/群/成员/轮次隔离，取消先使旧轮次失效，网络返回后条件提交，防止旧流程覆盖新会话。
- 提示发送失败、权限不足、成员批次不明时转人工；重连给完整验证时间，不追罚离线期间过期成员。
- 宽限期答错不重置完整时限；审批或移出结果不明时不自动重放。
- JSON 原子替换、先落盘后发布内存；损坏文件不自动覆盖为空配置。
- 配置含密钥，状态含 QQ 标识、来源及必要审批记录；不要上传运行目录或 `.env`，不保存日常聊天原文。
